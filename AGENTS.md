# Slate: agent notes

Slim PostgreSQL desktop client (Electron + React + CodeMirror 6). Read `README.md` first. Scope is deliberately small: connect, browse schema, run queries, AI autocomplete. Leave out admin features (roles, backups, server stats, table designers) unless asked.

- **Check your work**: `npm run typecheck`, `npm test`, then `npm run test:e2e`. The DB tests and e2e need `npm run db` running (embedded Postgres on 55432, no Docker). e2e screenshots in `test-results/e2e` are the quickest way to see UI changes.
- **Electron binary**: Electron 44 doesn't download its binary on install; the `postinstall` script (`install-electron`) does it.
- **Process split**: all database and Anthropic calls run in `src/main`. The renderer is sandboxed and talks only through `window.slate.api`. Adding a call means adding it to the `Api` interface and `API_METHODS` in `src/shared/api.ts` and implementing it in `src/main/index.ts`. Errors cross IPC as values, so the renderer sees the plain message.
- **Query execution** (`src/main/db.ts`): one `pg.Client` per tab (transactions span runs), scripts split by `src/shared/sql.ts`, each statement read through `pg-cursor` with `rowLimit + 1` rows. Values stay raw text (custom type parser), so the grid shows what Postgres prints. Error positions are converted to absolute offsets in the submitted SQL. `txStatus` comes from ReadyForQuery messages.
- **AI** (`src/main/ai.ts`, `src/renderer/src/editor/ghost.ts`): default model `claude-opus-5-5` at `effort: low`; Opus/Sonnet requests add `fallbacks: "default"` with the `server-side-fallback-2026-07-01` beta. The schema text (`schemaText.ts`) goes in a cached system block. Only schema and editor text are sent, never row data; keep it that way. Ghost text is requested only after typed input, at the end of a line, and not while the completion popup is open.
- **Variables** (`src/shared/variables.ts`): `:name` / `$1` placeholders are found with the same tokenizer as the statement splitter, so strings, comments, casts and dollar bodies are skipped. Values are inlined as quoted literals (`quoteLiteral`), not bind parameters, because untyped literals resolve in contexts where parameters fail (`:x is null`, `interval :d`). `bindVariables().map` converts error positions back to the original text. The renderer refuses to run with missing values, and main checks again. Per-environment values are stored in `settings.environmentVariables`. `resolveVariables()` merges them under the tab's own values: a key the tab has set, even to '' or NULL, wins, and `setVariable(..., undefined)` reverts to the environment's value. Main only ever receives the merged values.
- **Diagram** (`src/renderer/src/diagram/layout.ts`, `components/DiagramView.tsx`): dagre lays out related tables left to right, and tables without relationships go in rows underneath. Everything is plain SVG with colors and fonts as attributes, so PNG and SVG export is just serializing the content group. Pointer capture starts only once a drag moves, otherwise double-clicks never reach the table.
- **Environments**: `environment` and `databaseEnvironments` live on the connection; `environmentOf()` in `src/shared/types.ts` resolves them. The production guard is in the store's `run()` and uses `isReadOnly()` from `src/shared/sql.ts`, which errs towards treating a statement as a write. Saving a connection only reconnects when `connectionChanged()` is true or a new password was typed.
- **Secrets**: connection passwords and the API key are sealed with `safeStorage` in `store.ts` and never returned to the renderer (`hasPassword` / `apiKeySource` only).
- **Styling**: colors are CSS variables in `styles.css` for both themes; the CodeMirror theme reads the same variables. Use the variables rather than hard-coded colors.
- **History**: the history pane replaced tabs and sits between the explorer and the workspace. It shows only `historyFor(tabs, currentTarget)`; `currentTarget` (the database you are in) is set by `selectDatabase` (explorer clicks), `setActiveTab`, `newTab`, `moveTab`, `openTable` and `openDiagram`. Blank entries (no SQL, name or run) are pruned with `withoutBlanks` when you leave them. A `Tab` in the store is a history entry, persisted with `createdAt`, `touchedAt` and `lastRun`. The list sorts by `touchedAt`, which a run or a table opening updates; selecting or typing doesn't, so entries don't jump around. Each entry gets its own DB session; main closes sessions idle for 15 minutes unless a transaction is open.
- **Read-only production**: the store passes `readOnly` to `runQuery` for Production unless the user confirmed the writes; `db.run` sets `default_transaction_read_only` on every such run, because a SET inside a rolled-back transaction is undone. SQLSTATE 25006 in the results offers `retryWithWrites`.
- **macOS**: `macMenu()` in `src/main/index.ts` provides the Edit menu that Cmd+C/V need and leaves out Reload. electron-builder only builds mac targets on macOS (`npm run dist:mac`, or the GitHub workflow).
- **Not verified yet**: real Claude completions (no API key on this machine; e2e uses a mock server via `ANTHROPIC_BASE_URL`). The app has not been run on a Mac yet (it was built and tested on Windows only), and neither has Linux.
