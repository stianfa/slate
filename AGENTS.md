# Slate: agent notes

Slim PostgreSQL desktop client (Electron + React + CodeMirror 6). Read `README.md` first. Scope is deliberately small: connect, browse schema, run queries, AI autocomplete. Leave out admin features (roles, backups, server stats, table designers) unless asked.

- **Check your work**: `npm run typecheck`, `npm test`, then `npm run test:e2e`. The DB tests and e2e need `npm run db` running (embedded Postgres on 55432, no Docker). e2e screenshots in `test-results/e2e` are the quickest way to see UI changes.
- **Electron binary**: Electron 44 doesn't download its binary on install; the `postinstall` script (`install-electron`) does it.
- **Process split**: all database and AI calls run in `src/main`. The renderer is sandboxed and talks only through `window.slate.api`. Adding a call means adding it to the `Api` interface and `API_METHODS` in `src/shared/api.ts` and implementing it in `src/main/index.ts`. Errors cross IPC as values, so the renderer sees the plain message.
- **Query execution** (`src/main/db.ts`): one `pg.Client` per tab (transactions span runs), scripts split by `src/shared/sql.ts`, each statement read through `pg-cursor` with `rowLimit + 1` rows. Values stay raw text (custom type parser), so the grid shows what Postgres prints. Error positions are converted to absolute offsets in the submitted SQL. `txStatus` comes from ReadyForQuery messages.
- **AI** (`src/main/ai.ts`, `src/renderer/src/editor/ghost.ts`): Azure OpenAI through `AzureOpenAI` from `openai`, Responses API with `reasoning.effort: 'low'`. `Store.aiConfig()` merges Settings (`aiEndpoint`, `aiDeployment`, `aiApiVersion`, sealed `aiApiKey`) over the `AI_FOUNDRY_*` variables; endpoint and deployment are never committed. The endpoint is cut to its origin, so a full request URL works. The schema text (`schemaText.ts`) goes first, in the system message, so Azure's automatic prefix caching applies. Only schema and editor text are sent, never row data; keep it that way. Ghost text is requested only after typed input, at the end of a line, and not while the completion popup is open.
- **Chat** (`components/ChatPanel.tsx`, `AiCompleter.chat`): per-query conversation in `Tab.chat` (persisted), answered with the Responses API at `effort: 'medium'` and streamed to the renderer over the `CHAT_DELTA` channel (`onChatDelta` on the bridge). The system message is the instructions plus schema text, so it stays cacheable; the editor text and the last run's error message (not its detail) ride along with the newest user message. Like autocomplete, it never gets row data.
- **Variables** (`src/shared/variables.ts`): `:name` / `$1` placeholders are found with the same tokenizer as the statement splitter, so strings, comments, casts and dollar bodies are skipped. Values are inlined as quoted literals (`quoteLiteral`), not bind parameters, because untyped literals resolve in contexts where parameters fail (`:x is null`, `interval :d`). `bindVariables().map` converts error positions back to the original text. The renderer refuses to run with missing values, and main checks again. Per-environment values are stored in `settings.environmentVariables`, and global values under its `global` key. `environmentValues()` in `src/shared/types.ts` merges the two (the environment wins); unmarked databases get only the global values. `resolveVariables()` merges them under the tab's own values: a key the tab has set, even to '' or NULL, wins, and `setVariable(..., undefined)` reverts to the environment's value. Main only ever receives the merged values. The list under a field in `VariablesBar` comes from `suggestValues()`: the environment's value, the global one, other history entries' values (most recent first), then other environments'. `$1` gets none, since it means something different in every query.
- **Sidebar filter** (`components/Sidebar.tsx`): matches database names and table names. Tables come from loaded schemas, or from `tableNames` filled by `searchAllDatabases()` in the store, which the user starts from the hint under the tree. That search calls `db.tableNames()`: names only, on a one-off `pg.Client` closed straight after, one database at a time per server, so it never opens a pool per database. Its timeout is `SET LOCAL statement_timeout` in a read-only transaction plus pg's client-side `query_timeout`, not a startup parameter, because PgBouncer can refuse those. Don't run it automatically.
- **Diagram** (`src/renderer/src/diagram/layout.ts`, `components/DiagramView.tsx`): dagre lays out related tables left to right, and tables without relationships go in rows underneath. Everything is plain SVG with colors and fonts as attributes, so PNG and SVG export is just serializing the content group. Pointer capture starts only once a drag moves, otherwise double-clicks never reach the table.
- **Environments**: `environment` and `databaseEnvironments` live on the connection; `environmentOf()` in `src/shared/types.ts` resolves them. The production guard is in the store's `run()` and uses `isReadOnly()` from `src/shared/sql.ts`, which errs towards treating a statement as a write. Saving a connection only reconnects when `connectionChanged()` is true or a new password was typed.
- **Workspace persistence**: history and layout go to `workspace.json` through `loadWorkspace`/`saveWorkspace` (main writes atomically). Saves are debounced, and `beforeunload` flushes through the synchronous `saveWorkspaceNow` channel. Nothing is saved before `init()` has loaded the file, so it can't be overwritten with defaults. `init()` migrates the old `slate:workspace` local-storage entry once.
- **Transactions**: `requestDelete` / `requestMove` / `requestDisconnect` ask before rolling back an open transaction (judged from the entry's last `txStatus`). Main asks before quitting (`confirmQuit`, using `db.openTransactions()`) and flags sessions that drop mid-transaction (`lostTransactions`).
- **Editing rows** (`src/shared/changes.ts`, `DataGrid.tsx`): result fields carry the table OID and attribute number from RowDescription, and the schema carries `oid` / `num`, so `editTarget()` finds the table without another query. It refuses joins, views, repeated columns and a schema older than the result. Its `key` lists the fields holding the primary key; without all of them only new rows can be added (`readOnlyReason()`). Pending changes live in `Tab.changes` (runtime only, `GridChanges`): `added` rows (`undefined` is DEFAULT, `null` is NULL), `edited` cells by result row index and field index, and `deleted` row indexes. `withEdit` drops an edit that goes back to the loaded value. `changeStatements()` plans one DELETE (by key), an UPDATE per edited row (WHERE on the key as loaded) and one INSERT, each with the row count it must touch, all with quoted literals and `RETURNING` the result's fields. `db.applyChanges` runs them on the tab's session inside `BEGIN`/`COMMIT`, or `SAVEPOINT slate_changes` when a transaction is open, and rolls back on an error or a wrong row count. `rowsAfter()` then updates the same result object with the same `fields` array, which is what keeps the grid from resetting. A run asks before it drops unsaved changes; Load more and Transpose are disabled while there are some. The grid remembers its last copy (`lastCopy`) so pasting it back keeps NULLs and line breaks; other text is parsed as TSV with empty values as NULL. Clipboard reads go through `readClipboard` in main, like `copyText`, and e2e stubs both.
- **Sort and filter** (`lib/rows.ts`, `components/ColumnMenu.tsx`): `rowOrder()` sorts and filters the loaded rows only, never re-running the query: the text filter, plus value filters picked in the column header's right-click menu (`ColumnFilter`, include or exclude, NULL is a value). `distinctValues()` lists a column's values only below `MAX_PICK_VALUES` (50). The state is `Tab.view` (runtime only, reset by a run). DataGrid works in display rows and maps them to result rows through `shown`; edits and deletions are always keyed by the result row index, so they survive a change of sort or filter.
- **Results**: `loadMore` re-runs only read-only statements. `db.exportCsv` streams on a pool connection inside `BEGIN READ ONLY`. In e2e, the native save dialog is replaced via `app.evaluate`.
- **Shortcuts**: app-wide keys are in `useShortcuts()` in `App.tsx`, which skips events something else already handled (`defaultPrevented`), so the grid's Cmd+C or the editor's own keys win. Keys that change a query (delete, commit, rollback) are ignored while a dialog or the palette is open. Editor shortcuts with Alt (`Shift+Alt+F`, `Alt+\`) match `event.code`, because CodeMirror doesn't match Option combinations by name on macOS, where they type characters.
- **Palette and formatting**: `CommandPalette.tsx` builds its items from store state each time it opens, with fuzzy matching in `lib/fuzzy.ts`. `editor/format.ts` wraps sql-formatter's PostgreSQL dialect and treats `:name`/`$1` as parameters.
- **Secrets**: connection passwords and the Azure API key are sealed with `safeStorage` in `store.ts` and never returned to the renderer (`hasPassword` / `aiKeySource` only).
- **Styling**: colors are CSS variables in `styles.css` for both themes; the CodeMirror theme reads the same variables. Use the variables rather than hard-coded colors.
- **History**: the history pane replaced tabs and sits between the explorer and the workspace. It shows only `historyFor(tabs, currentTarget)`; `currentTarget` (the database you are in) is set by `selectDatabase` (explorer clicks), `setActiveTab`, `newTab`, `moveTab`, `openTable` and `openDiagram`. Blank entries (no SQL, name or run) are pruned with `withoutBlanks` when you leave them. A `Tab` in the store is a history entry, persisted with `createdAt`, `touchedAt` and `lastRun`. The list sorts by `touchedAt`, which a run or a table opening updates; selecting or typing doesn't, so entries don't jump around. Each entry gets its own DB session; main closes sessions idle for 15 minutes unless a transaction is open.
- **Read-only production**: the store passes `readOnly` to `runQuery` for Production unless the user confirmed the writes; `db.run` sets `default_transaction_read_only` on every such run, because a SET inside a rolled-back transaction is undone. SQLSTATE 25006 in the results offers `retryWithWrites`.
- **macOS**: `macMenu()` in `src/main/index.ts` provides the Edit menu that Cmd+C/V need and leaves out Reload. CI signs the app with a self-signed certificate (secrets `MAC_CERT_P12`, `MAC_CERT_PASSWORD`; `scripts/sign-mac.cjs` as electron-builder's `afterSign`) so the designated requirement stays the same across builds; `safeStorage` secrets depend on it. Ad-hoc builds lose keychain access on every update, and `Store` then reports the saved password as unreadable instead of passing null to pg. electron-builder only builds mac targets on macOS (`npm run dist:mac`, or the GitHub workflow).
- **Not verified yet**: real Azure OpenAI completions (e2e uses a mock server via `AI_FOUNDRY_URL`). The app has been run and tested on macOS only, not on Windows or Linux.
